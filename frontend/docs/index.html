Set up an AI analyst for Argus

Argus separates camera viewing from visual intelligence. Pick the setup that matches your hardware — everything below runs against the same app, switched from AI setup in the sidebar.

Overview

There are four ways to connect an analyst. None are required to view cameras, manage sources, or use CPU-based motion/face/people detection — those work with no model at all.

No GPU needed

Camera viewing only

Sources, uploads, rules, activity feed. No model calls of any kind.

No GPU needed

CPU tools (OpenCV)

Motion, brightness/blur, face and people detection running directly on the Argus host.

CPU-friendly

Local or hosted vision API

Point Argus at any OpenAI-compatible /v1/chat/completions endpoint that accepts images — Ollama, llama.cpp, or a hosted provider.

Requires NVIDIA GPU

Embedded Qwen2.5-VL

Runs the vision-language model in-process on the Argus host. Needs CUDA and ~20GB VRAM.

Saving AI setup never contacts a model. Use Test vision connection to send one synthetic red image and confirm the path works before relying on it.

CPU tools (OpenCV) NO MODEL REQUIRED

Every Argus install — with or without a GPU — runs a set of classical computer-vision measurements per camera in the background. These are not AI in the model-inference sense: no weights are downloaded and nothing is inferred about identity or intent.

What it measures

FeatureHowOutput
MotionFrame differencing + thresholding inside your chosen watch area% of pixels changed, bounding boxes of the changed regions
Brightness / low lightMean pixel value of the watch area0–255 brightness score, flag below a configurable threshold
Sharpness / blurVariance of the LaplacianEdge-detail score, flag below a configurable threshold
FacesHaar-cascade classifier (haarcascade_frontalface_default.xml, bundled with OpenCV)Face count and boxes, sampled every few seconds
PeopleHOG descriptor + built-in pedestrian SVMPerson count and boxes, sampled every few seconds
ObjectsYOLOv8n, a small object-detection model that runs entirely on CPU80 everyday object types (person, car, dog, backpack, and more) with confidence and boxes

Face, people and object detection are heavier than motion, so they run on a slower cadence and only when enabled — they never affect the motion/brightness sampling rate. Toggle each on the CPU tools page, along with an optional cooldown so repeated detections don't spam the activity feed.

These are pixel-level and small-model measurements, not the judgment a vision model gives you. A moving shadow can register as motion; a poster of a face can register as a face; object detection can miss unusual angles or lighting. Treat results as a fast, free first signal — pair with a vision model (below) when you need identity, context, or natural-language answers.

Alert rules without a vision model

On the Rules page, choose CPU object detection as the rule source and pick a class from the list (person, car, backpack, etc.) — the rule fires whenever object detection is enabled on that camera and finds a match, with no vision model connected at all. Choosing AI vision model instead lets you describe anything in plain language ("a person carrying a backpack"), but only works once a model is connected in AI setup.

Ollama

Ollama is the fastest way to run a local, CPU-or-GPU vision model behind an OpenAI-compatible API.

1. Install Ollama

# macOS / Linux
curl -fsSL https://ollama.com/install.sh | sh

# Windows: download the installer from ollama.com

2. Pull a vision-capable model

ollama pull gemma3:4b
# or: llava, llama3.2-vision, qwen2.5vl (any tag Ollama lists as vision-capable)

3. Point Argus at it

In AI setup, choose Local or hosted vision API and click the Ollama preset button, or enter manually:

FieldValue
API base URLhttp://localhost:11434/v1
Vision model namegemma3:4b (must match the tag you pulled)
API keyleave blank

If Ollama runs on a different machine than Argus, use that machine's address instead of localhost, and check "allow frames to be sent outside this machine".

4. Test the connection

Click Test vision connection. A pass means the streaming /chat/completions call with an image succeeded end to end. Restart Ollama or change models and you'll need to re-test.

llama.cpp

llama.cpp's llama-server exposes the same OpenAI-compatible API for GGUF vision models, with fine-grained control over quantization for lower-end CPUs.

1. Build or install llama-server

git clone https://github.com/ggml-org/llama.cpp
cd llama.cpp
cmake -B build -DGGML_CUDA=OFF   # omit -DGGML_CUDA=OFF if you have an NVIDIA GPU
cmake --build build --config Release -j

2. Download a GGUF vision model + its mmproj file

Vision models in GGUF form ship as two files: the language model and a multimodal projector (mmproj-*.gguf). Both are required. See llama.cpp's multimodal docs for supported architectures.

3. Start the server with an explicit alias

./build/bin/llama-server \
  -m model.gguf \
  --mmproj mmproj-model.gguf \
  --alias argus-vision \
  --host 0.0.0.0 --port 8080

4. Point Argus at it

Choose Local or hosted vision API and click llama.cpp preset, or enter manually:

FieldValue
API base URLhttp://localhost:8080/v1
Vision model nameargus-vision (must match --alias)
API keyleave blank unless you set --api-key

Same networking note as Ollama: if llama-server runs on a different machine, use that machine's address instead of localhost.

Hosted vision API

Any provider exposing an OpenAI-compatible, image-capable /v1/chat/completions endpoint works the same way — enter its base URL (including /v1), the exact model name it expects, and an API key if required.

  • Sampled frames are sent to that provider over the network. Charges may apply per their pricing.
  • Keys are stored in a private settings file on the Argus server, excluded from Git and never returned by the settings API — this is file protection, not encrypted secret storage.
  • Argus requires explicit permission (a checkbox) before sending frames to any non-loopback server.

There is no automatic failover between providers. If the hosted endpoint is unreachable, chat returns an explicit error; camera viewing keeps working.

Embedded Qwen2.5-VL NVIDIA GPU REQUIRED

Runs Qwen/Qwen2.5-VL-7B-Instruct directly inside the Argus backend process — no separate server. This is the heaviest option and needs a prepared GPU environment.

Requirements

An NVIDIA GPU with at least 20GB of VRAM. Choose Embedded Qwen in AI setup — Argus checks your hardware and tells you whether it's usable.

A detected GPU does not guarantee sufficient free VRAM. The first Test vision connection click may take a while — it can trigger a multi-GB weight download the first time.

Troubleshooting

"Test vision connection" fails

  • Confirm the base URL includes /v1 and is reachable from the machine running Argus.
  • Confirm the model name matches exactly what the server reports (ollama list, or the llama.cpp --alias).
  • Restarted the model server since the last test? Test again — connections aren't re-validated automatically.

CPU tools show "warming up" indefinitely

The source may be offline, or the CPU worker hasn't produced a sample yet. Check Health for the source's online status.

Face/people counts look wrong

Haar cascades and HOG pedestrian detection are fast but dated CV techniques — they miss side-on faces, partial occlusion, and unusual poses, and can false-positive on textured backgrounds. They're a free, always-on first signal, not a calibrated accuracy claim.
